CDAutoTest 自动化测试框架 · API 文档

CDAutoTest 是一套面向 Web 应用的端到端自动化测试框架，以 JUnit4 + Selenium WebDriver 为底座， 集成了 Allure 报告、覆盖率采集、邮件通知与软件质量评估模型。本文档描述框架自身的 API， 供编写与维护自动化用例的同学查阅。

包的组织方式

首页按职责对包做了分组，建议按下面的顺序阅读：

  1. 核心框架：App（启动入口）、Sys（配置与全局静态对象）、 Sut（被测件版本信息）、AutoTest（执行引擎）；
  2. 基础工具库：Base（G 系列通用工具：文件 / 时间 / 断言 / 日志）、 IO（CSV / Excel / JSON 导入导出）、DB（数据库校验）、 Net、Mail、DT（日志与业务对象）；
  3. 测试执行与数据模型：Test（测试计划与调度）、 DUnit（运行单元 / 属性 / 动态数据）、Tclg（测试类群）、 Detail；
  4. Web 自动化：Webdriver（驱动管理、控件操作、等待与重试）， page 及其子包（页面对象模型）；
  5. 报告与质量：Html、Coverage、Quality；
  6. 组件与示例：Dragon（桌面提示气泡）、testdemo（用例模板）。

命名约定

  • 以 G 开头的类是全局工具类或全局数据单元（Global / General），例如 GFile、GLog、GParam；
  • 以 GWCtrl 开头的类是 WebDriver 控件级操作封装，例如 GWCtrlInputFill、GWCtrlWait；
  • page.widget 下的类对应跨页面复用的 UI 控件， page.page 下的类对应具体业务页面。

快速上手

编写一个用例通常需要三样东西：

  • 从 Webdriver 包获取浏览器驱动与等待工具；
  • 用 page 包中的页面对象描述要操作的界面；
  • 用 Base.GAssert 做结果断言，用 DT.GLog 输出日志。

文档自身的约定

  • 文档中的 @version 采用 yyyyMMddHHmmss 时间戳；
  • 标注了"当前实现未使用"的字段或参数，是为后续扩展保留的配置项，调整它们不会改变现有行为；
  • 方法注释中的 @throws 只列出会向外传播、需要调用方处理的异常。
